# UX Checklist

21 items. Use this checklist before Phase 5 delivery.

1. The problem brief is signed off by the user.
2. Primary user and context are specific.
3. Core tasks are expressed as user actions.
4. Success criteria are observable.
5. Guardrails and constraints are recorded.
6. Page count is intentional and between one and five.
7. Every page has a clear entry path.
8. Every page has a clear exit or return path.
9. References include Steal, Adapt, and Reject decisions.
10. Wireframe boxes include Order, Label, Intent, and Why here.
11. Reading order starts at 1 on every page.
12. Primary action is visually dominant and not crowded by equal CTAs.
13. Data regions define default, empty, loading, and error states.
14. Mobile, tablet, and desktop layout behavior is described.
15. Visual design preserves wireframe order and intent.
16. Every primary task has a clickable demonstration path.
17. State switcher can toggle default, empty, loading, and error states.
18. Toggles, filters, selections, masks, timers, and counters actually change state.
19. flow.html, wireframe.html, and visual.html use the same page IDs.
20. Cross-page state is represented when one page depends on another.
21. Accessibility baselines pass: readable type, visible focus, contrast, and touch target size.

## Failure Handling

If any item fails, return to the relevant phase:

- Items 1-6: Phase 1.
- Items 7-15: Phase 2 or 3.
- Items 16-21: Phase 4.
